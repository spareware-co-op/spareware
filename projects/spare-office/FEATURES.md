# Spare Office: everything to build

*Stage: Mapping. This list is written from [features.json](features.json), which holds the same map as data. The architecture is in [ARCHITECTURE.md](ARCHITECTURE.md) and the work board in [STATUS.md](STATUS.md).*

Spare Office replaces Microsoft 365: Word, Excel, PowerPoint, Outlook, Teams, OneNote, OneDrive and Forms. Documents, spreadsheets, slides, mail and calendar, chat and meetings, notes, forms and file storage in one suite that is free to use and free to join. Files save in open formats, Microsoft's formats are read and written from their published standards, and people, scripts and AI agents all use the same commands. This map works top-down so nothing is missed: 21 areas a full replacement needs, 275 features a person can use, and 641 buildable parts under them. Each feature is marked **core** (needed for a first usable release, 159 features), **next** (soon after, 80) or **later** (36). Spare Office keeps only its own rules: where [Spare Kit](../kit/FEATURES.md) already maps a part, the Office part depends on that kit part by its ID (KIT-...) and adds only what an office suite needs. Parts also name kit crates (kit-...), shared engines (engine-...) and other Office parts by ID. Every app's actions are command schemas, so the command API and MCP server are core: anything a person can do, a script or an agent can do through the same commands. Where a work-board piece already covers a part, its ID links to that board. Piece OF07 (first app to build) decides which app's core features come first. IDs are permanent: a gap in the numbering is a part that moved to the kit or merged into another part, never something missing. Microsoft's product names appear only to say what we replace; every Spare app has its own name, look and icons.

## Questions for assessing this map and its demo

- Walk through a normal working day (read mail on a phone, join a meeting, edit a shared sheet with others, fill a form, find an old file): does every step land on a core feature, including the phone-sized browser layouts and web push, or is something missing?
- Are the core features truly the smallest set for a first usable release? Does piece OF07 (first app: Write, Sheets or Mail) change which core features must come first?
- Partner or build (piece OF01): which parts would ArtCraft's office apps or LibreOffice's engine already cover, and how much of the document core and file formats does that remove?
- File fidelity: how will we prove files look the same in Word, Excel and PowerPoint using only published standards and openly licensed test files, never by reverse-engineering Microsoft's software?
- Co-editing (pieces OF03 and A05): is the operation log plus a text CRDT enough to promise no lost work, including after days offline?
- Mail: should the co-op run its own mail service at launch, given deliverability work, MTA-STS and DMARC on every hosted domain, quarantine and spam abuse, or start as an app for existing mail providers?
- Chat and meetings (piece OF05): the kit now owns the one chat server and call service; is Matrix or our own protocol right for them, and are AGPL servers acceptable as separate services under our licence rules?
- Which parts carry real running costs (storage, mail, meeting servers, speech recognition, AI), and what free allowance can members afford to vote for?
- AI: does the demo make it clear the assistant is off until turned on, the person and their organisation pick the provider, content never trains a model, and an agent must ask a person before it sends mail, shares outside or deletes?
- Accessibility: can canvas-drawn editors really work with every screen reader? Is the accessible mirror part sized and scheduled early enough?
- Indigenous languages, starting with te reo Māori: who are our language and data-sovereignty partners for the interface, dictionaries, macron autocorrect, sorting, maramataka, speech models and voices, and are they involved from the start?
- Legal: which legal parts need a lawyer before launch (privacy and IPP 3A, health information, telecommunications interception duties, harmful digital communications, illegal content, recording consent, electronic signatures, booking payments, overseas tax, import terms, Exchange protocol clearance)?
- Scope edges: do video editing, diagramming, project scheduling, intranet sites, rosters, a video library, dashboards, low-code apps, Access databases and Publisher files belong in Spare Office, in Spare Studio or Spare Work, or later?
- Moving in: do Microsoft's and Google's API terms allow our import tools, and what happens to chat history that can't be exported?
- Are the part sizes believable? Which large parts should become new work-board pieces next?
- Public sector and schools: do we target government agencies and schools early, starting with New Zealand's (Public Records Act, the New Zealand Information Security Manual, Secure Government Email, classification labels, class notebooks, assignments and LTI) or later?
- Does the demo use only our own names, look and icons, with Microsoft's product names appearing only to say what each app replaces?
- Headless: does the demo show one task done by a person, a script and an agent through the same commands, with every Office app's command schemas in the command API and MCP server from the first release?
- Safe files: does the demo open hostile test files (remote templates, DDE fields, macros, booby-trapped zips) without fetching or running anything, and serve every upload from a separate domain?
- Leaving: can an admin take a whole organisation out in open formats and close it, can a person's export include version history and comments, and can a suspended person still export and appeal?
- Kit dependencies: Office's first release needs the kit's regular payments, business accounts and desktop sync client to be core, and several parts say they belong in the kit or engines (speech, text recognition, domain checks, account switching, the organisation audit log, link checks, the separate file domain, the form engine). Have the kit and engines taken them on?
